# Q-Link

**v0.1.2**

一个跑在你自己电脑上的 QQ 机器人控制台：用手机 QQ 扫码接入 QQ 开放平台，然后在同
一个界面里调教它的**人设、记忆、关键词、名单表、违禁词、表情包、梗知识**，改完即时生效。
可以同时管理多台机器人，每台都有完全独立的一套配置。

界面沿用 QQ 客户端默认的蓝白配色与布局（白面板、`#F2F3F5` 侧栏、`#12B7F5` 品牌蓝、
`#0099FF` 主操作蓝），左侧分组导航 + 右下内容区，左下角是当前机器人，列表类功能用
QQ 的「联系人列表 + 详情」双栏结构。顶栏可一键切换**黑夜模式**（黑蓝配色），选择会被记住。

有两种跑法，**后端是同一份代码**：

| 方式 | 怎么开始 | 特点 |
| --- | --- | --- |
| 命令行 | `npm start`，浏览器打开 `127.0.0.1:3200` | 开发方便 |
| **桌面版** | 双击 `启动桌面版.bat` | 无系统标题栏、**外壳配色跟随主题**；关窗不退出，驻留托盘，机器人保持在线 |

> 想系统了解每个功能怎么用，启动后打开控制台里的 **文档** 页，那里有一份完整教程。

## 快速开始

**最简单的方式：双击项目里的 `启动控制台.bat`**（macOS / Linux 用 `启动控制台.command`）。

它会自动检查 Node、首次运行时装好依赖、启动服务，然后帮你打开浏览器。关闭那个窗口
就是停止机器人。

想手动来也可以：

```bash
npm install
npm start
```

然后打开 <http://127.0.0.1:3200>。

> 如果提示端口被占用，说明控制台可能已经在运行了，直接访问上面的地址即可；
> 想换端口：`set PORT=3300 && npm start`。
> 远程 / 无桌面环境下不想自动开浏览器：设 `QQBOT_LAUNCH_NO_OPEN=1`。

### 关于「单个 HTML 文件」

整个控制台界面会被打包成一个自包含的文件：**`public/console.html`**（约 134 KB，
HTML + CSS + JS 全部内联，不含任何外部 js / css 引用）。`npm start` 时服务会自动重建它，
所以它不会和你改的源码脱节。

但有一点绕不过去：**这个文件不能直接双击打开**。它必须配合本机的 Node 服务运行，因为
下面三件事只能在服务端做：

- 用 AppSecret 换 access_token
- 连接 QQ 的 WebSocket 网关长连接
- 调用官方接口发消息

浏览器直接调 `api.bot.qq.com` 会被跨域策略拦住（这一点我没有真实凭据，无法验证是否
一定失败，但不能依赖它）；而且扫码绑定用的官方 SDK 是 Node 包，浏览器里跑不了。
所以直接双击 `console.html` 时，页面会显示一句明确的指引，而不是白屏。

想改界面的话，源码仍然是拆开的模块（`public/index.html`、`public/css/`、`public/js/`），
改完执行 `npm run build` 重新生成单文件版即可，或者用 `npm run build:watch` 让它自动重建。

## 首次运行要做的三件事

### 1. 接入 QQ 机器人

进入**接入配置**，二选一：

- **扫码绑定（推荐）**：点「生成二维码」→ 手机 QQ 扫码 → 选择要绑定的机器人 → 确认。
  AppID 与 AppSecret 会自动写入配置，不用手抄。
- **手动填写**：从 [QQ 开放平台](https://q.qq.com/#/apps) → 机器人 → 开发设置里复制
  AppID 与 AppSecret 填进去。

填完点「测试连接」，看到机器人昵称就说明凭据有效。

> 还没创建过机器人？[点这里快速创建一个](https://q.qq.com/qqbot/openclaw/login.html)，
> 登录后点「创建机器人」即可，几秒钟就好。

### 2. 配置 AI 模型

进入 **AI 模型**，填三项：接口地址、API Key、模型名称。任何兼容 OpenAI
`/chat/completions` 协议的服务都能直接用，页面里给了 DeepSeek、阿里云百炼、智谱、
月之暗面、本地 Ollama 的快捷预设，点一下自动填好。填完点「测试连接」。

### 3. 启动

回到顶栏点「启动机器人」。状态胶囊变成绿色的「在线」就成功了。现在用手机 QQ 给机器人
发条消息试试。

## 控制台能做什么

| 页面 | 解决什么问题 |
| --- | --- |
| **概览** | 是否在线、配了什么、最近聊了什么，一屏看完 |
| **接入配置** | 扫码 / 手动接入、沙箱切换、事件订阅（intents）勾选、**平台权限**（能本机控制的开关 + 从平台读回真实状态）；扫码成功后自动上线 |
| **AI 人设** | 机器人昵称与头像（本地上传）；**语气 / 回复长度 / 表情使用程度 / 幽默感 / 主动性 / 用词正式度 全部是滑杆**，左右端写含义、实时显示当前数值；风格描述与开场问候仍是文本；右侧**实时试聊窗口**用同一条链路预览效果 |
| **记忆库** | 全局 / 单聊 / 群聊三个层级的长期记忆，支持手动添加与自动提取 |
| **关键词** | 触发式记忆：平时不占上下文，提到关键词才把详情取出来，避免忘掉重要的事；支持别名、优先级、命中测试，也能由机器人自动添加 |
| **名单表** | 白名单 / 黑名单，每个人的**「对他的态度」是一根滑杆**（完全不回复 → 冷淡 → 照常 → 熟络 → 非常亲近）；可从「最近联系过的人」（只列聊满 3 条以上的）一键拉入，也可**手动添加**并填写备注名 / QQ 号（仅备注）/ openid；按 openid 匹配，改昵称也不会认错 |
| **违禁词** | 本地过滤用户输入与模型输出，动作可选拦截、替换、仅记录 |
| **表情包** | 上传图片并命名，模型在回复里写 `[sticker:名称]` 就会发图 |
| **梗知识** | 群里的黑话与新梗，命中时作为背景注入，让它接得住梗 |
| **AI 模型** | 模型接入、回复行为、名单态度默认值、各项功能开关、数据导出 |
| **消息日志** | 对话记录按**私聊 / 群聊**分列表，点进去看完整对话与对方信息（openid、昵称、名单归属、消息数）；另有连接层实时日志 |
| **文档** | 内置完整教程，左侧章节目录 + 右侧长文，含代码块、参数表格与提示块 |

### 多机器人

左下角显示当前机器人的头像和昵称，点一下就能切换、新建或删除。**删除需要等 5 秒倒计时**才能点确认，避免手快误删。

**每台机器人的配置完全独立**：登录凭据（AppID/AppSecret）、人设、记忆、关键词、名单、
违禁词、表情包、梗知识、会话上下文、消息日志，全部各存一份。切换机器人时，正在运行的
连接会先断开，再用新机器人的凭据重新上线（如果开了自动连接）。

数据落在 `data/bots/<机器人 id>/`，`data/bots.json` 是登记表与当前选中项。
从旧版（单机器人）升级上来时，原来的 `data/*.json` 会自动迁移成第一台机器人，不会丢配置。

### 一些设计上的取舍

- **试聊窗口是真的**：它走的是和线上完全相同的链路（关键词 → 违禁词 → 记忆 / 梗注入 →
  模型 → 输出过滤 → 表情包解析），所以预览里成立的效果，线上也成立。
- **违禁词分方向**：只筛输入、只筛输出、或双向。拦截用户输入时可以直接静默处理，也可以
  回一句你自己写的话术。
- **关键词能省钱**：「固定回复」不调用模型，高频问句用它，响应快也省钱。
- **群聊默认只回应 @**：群主开启「接收所有消息」后，把「群里只回应 @ 它的消息」关掉，
  它才会参与群里的闲聊。

## 桌面版

后端是同一份 `server/index.js`（拆出了 `startServer()` 供外壳调用），所以机器人的行为在两种跑法下完全一致。

```bash
npm run desktop          # 等价于双击 启动桌面版.bat
```

- **外壳跟随主题**：窗口去掉了系统标题栏，顶栏本身既是应用头部也是拖拽区，右侧给系统的最小化/
  最大化/关闭按钮留出精确宽度；切换白天/黑夜时，窗口底色与标题栏按钮区配色会一起变。
- **关窗不退出**：关闭窗口只是隐藏，进程驻留托盘，机器人继续在线。托盘菜单可显示窗口、
  打开数据目录、真正退出。
- **数据位置**：打包安装后放系统用户数据目录（Windows `%APPDATA%\q-link`，托盘菜单可直接打开）。
  未打包时若项目里已有 `data/` 就共用那一份，所以命令行版和桌面版切来切去配置不会丢。
  安装版是全新的一份 —— 想把现有配置带过去，把 `data` 文件夹整个复制过去即可。

### 打包

自动复用本机已装的 Electron，不需要先下载一遍：

```bash
node desktop/pack.mjs            # 解包目录（最快，用来验证打包结果能不能跑）
node desktop/pack.mjs portable   # 免安装单文件 exe
node desktop/pack.mjs nsis       # 安装向导 exe
node desktop/pack.mjs all
```

产物在 `dist/`。找不到 Electron 时用 `QLINK_ELECTRON` 指定 electron.exe 的完整路径。

## 测试

```bash
npm test              # 引擎单测 + 端到端集成测试
npm run test:engine   # 只跑规则链与提示词拼装的单测
npm run test:e2e      # 只跑端到端集成测试
```

两个测试都会把数据目录切到系统临时目录（通过 `QQBOT_DATA_DIR` 环境变量），
**不会动你正在用的 `data/`**。

`test/e2e.mjs` 会启动一个模拟的 QQ 开放平台（`test/mock-platform.mjs`），把官方接口按
文档行为实现一遍，然后用一份隔离的配置把真正的控制台跑起来，端到端验证：

- 鉴权：`appId/clientSecret` 换 token，并正确解析字符串形式的 `expires_in`
- 网关：Hello → Identify（`QQBot` 前缀 token、intents、shard）→ READY → 心跳/ACK
- 收消息：单聊与群聊事件解析、附件文本化
- 发消息：文字先行、`msg_id` 用事件的 `d.id`、`msg_seq` 从 1 递增、按 `msg_idx` 引用回复
- 富媒体：上传拿 `file_info` → `msg_type=7` 发图
- 规则链：关键词固定回复（不调模型）、输出侧违禁词替换、同 `msg_id` 重复推送去重
- 长文本：按上限拆分且 `msg_seq` 递增（规避 `40054005`）
- 重连：收到 4009 后用 `op 6 Resume` 带上 `session_id` 与 `seq`，并恢复在线
- 持久化：消息日志与各模块 JSON 落盘

这样在没有真实凭据的情况下，除「官方服务器是否按文档响应」之外的所有代码路径都被覆盖。

## 安全说明

- AppID / AppSecret / API Key 只写在 `data/config.json`，**只在本机使用**，不会发往
  任何第三方服务。
- 控制台**没有任何登录鉴权**，所以默认只绑定回环地址 `127.0.0.1`，只有本机能打开。
  绑定地址由 `QQBOT_HOST` 控制：

  ```bash
  npm start                              # 默认 127.0.0.1，仅本机可访问
  set QQBOT_HOST=0.0.0.0 && npm start    # 显式暴露到局域网（启动时会打印告警）
  ```

  确实需要从别的机器访问时，建议用 SSH 隧道而不是直接暴露：
  `ssh -L 3200:127.0.0.1:3200 user@服务器`，然后在本机浏览器打开 `http://127.0.0.1:3200`。
- 导出的配置文件（AI 模型页 → 导出全部配置）会自动剔除 AppSecret。
- 本地违禁词过滤是为了兜住你自己定义的边界，**平台的审核仍然独立生效**，两者不互相替代。
- 建议按官方要求每 3 个月重置一次 AppSecret。

## 两个高频问题

**关掉控制台，机器人还能用吗？——不能。**

Q-Link 就是运行在你这台电脑上的那个进程：它自己连 QQ 的 WebSocket 网关、收消息、调模型、
把回复发回去。关掉窗口（或电脑睡眠 / 关机）就等于断开网关连接，机器人立刻下线，
**这期间的消息不会补发**。腾讯那边只提供网关和 API，不托管你的机器人逻辑，
不存在一个"云端替你跑着"的副本。

想长期在线就把它放到一台一直开机的机器上（云服务器 / NAS / 旧电脑 / 树莓派），
用 pm2、systemd 或计划任务保活。重开控制台时，只要「扫码绑定成功后自动启动机器人」是开着的，
它会自己重新上线。

**openid 从哪里来？——不用申请，消息一到就自动记下来了。**

要复制时去这两个地方：

- 「名单表 → 最近联系过的人」：每张卡片下方那行等宽字就是；也可以直接点「加入白名单」，根本不用手抄。
- 「消息日志」：点开某个会话，右侧「对方信息」会分别列出 `单聊 openid`、`群 openid`（群本身）
  以及每个成员的 `群内 openid`。

三点注意：同一个人的**单聊 openid 与群聊 openid 不是同一个值**，群聊的还**按群区分**；
openid **按机器人（AppID）隔离**，换一台机器人就不通用。想让机器人把多个 openid 当成同一个人，
就在名单表里把它们都绑到同一个人身上。

## 平台本身的限制（不是没做，是官方接口不支持）

这几点查过官方文档（`api-v2` 全站接口索引、事件模型、运营规范），结论明确，所以控制台
按"能做到的最好方式"实现，并在界面上如实说明：

| 想做的事 | 官方接口的情况 | Q-Link 的处理 |
| --- | --- | --- |
| 把控制台里改的昵称/头像同步到 QQ | **不存在**修改机器人资料的接口。接口索引里「用户/机器人」分类只有 `GET /users/@me` 与 `GET /users/@me/guilds` 两个只读接口，全站 4 个 PUT 都与机器人资料无关 | 控制台里改的是本机显示的身份；另外提供「从平台读取」，把 QQ 那边的昵称头像读回来给你对照。要改 QQ 里显示的头像昵称，只能去 QQ 开放平台管理端 |
| 用 QQ 号识别用户 | **拿不到**。事件 User 对象里没有任何 QQ 号字段，官方原文写明这些 ID「与真实的 ID 无关」，运营规范 §5.10 还**明文禁止**获取或使用用户 QQ 号 | 名单表按 openid 识别。这反而更可靠：对方改昵称、换头像都不影响识别，不会出现「改个名字就认错人」 |
| 跨场景认出同一个人 | 单聊的 `user_openid` 与群聊的 `member_openid` **互不通用**，且 member_openid 是按群区分的；打通需要申请 `union_openid`（邮件申请、1~3 工作日、要求同一主体） | 一个人可以绑定多个 openid（单聊一个、每个群一个），绑到同一个人身上即可统一对待 |
| 显示对方头像 | 事件 User 对象里**没有** avatar 字段，也没有按 openid 反查用户资料的接口 | 用昵称首字生成的占位头像 |
| 单聊里显示对方昵称 | C2C 事件的 `author.username` 在官方示例里为空字符串 | 没有昵称时用 `用户 xxxxxx` 占位；你也可以在「名单表」里给他起备注名 |
| 「允许私聊 / 群聊 / 被搜索到 / 群管理能力」这些开关双向同步 | **没有任何可写的接口**。「用户/机器人」分类下只有 2 个只读接口；不存在 `/v2/bot/settings`、`/v2/settings` 之类的设置接口。这些开关在 QQ Bot 管理端「服务范围」里配，或由用户/群主在 QQ 客户端里点 | 拆成两半：**能本机控制的**（是否响应私聊 / 群聊）做成真开关，改了立刻生效；**只能读或只能去平台设置的**如实标注，并提供「读取群内真实状态」和「去管理端设置」的入口，绝不假装写入成功 |
| 群消息接收范围（全部 / 仅 @） | 有**只读**接口 `GET /v2/groups/{group_openid}/bot_state`，返回 `recv_msg_setting`、`allow_proactive_msg`、`member_role`，但文档标注「仅白名单机器人可用」（非白名单返回 11253） | 「接入配置 → 平台权限 → 读取群内真实状态」会去读，读得到就显示机器人实际身份与群主给的消息范围，读不到就直说读不到 |
| 在频道里开权限 | 总开关无接口。唯一支持的方式是 `POST /guilds/{guild_id}/api_permission/demand` **生成授权链接**，由频道主点击授权（每天每频道最多 3 条） | 做成「生成授权链接」按钮，把链接给你去发给频道主，而不是做一个假的开关 |

## 尚未实现

- **Webhook 事件模式**：当前只用 WebSocket 长连接。Webhook 需要公网 HTTPS 与 Ed25519
  签名校验，本地控制台场景下意义不大，因此没有做。
- **频道（guild）场景**：单聊与群聊已完整支持；`AT_MESSAGE_CREATE` 等频道事件会被接收
  并记录，但回复走的是频道接口，未实现。
- **语音 / 视频 / 文件回复**：`attachments` 会被读取并转成文字描述交给模型，但机器人只会
  发出文字与图片。
- **引用消息里带图**：文本引用已支持，图片引用未做。

## 开发笔记

- **图标**：Q-Link 的标识是内联 SVG 自绘的（一道心跳线 + `Link` 字样），没有使用任何
  QQ 官方素材 —— 官方 logo 是注册商标，直接拿来做第三方工具的头像有风险，所以重新画了一个。
  favicon 在 `npm run build` 时从顶栏这一个 SVG 自动派生，两处永远一致。
- **滑杆分档要在两处保持一致**：`public/js/pages/lists.js` 的 `ATTITUDE_BANDS` 与
  `server/data.js` 的 `attitudeToMode` 是同一套区间。`test/engine.mjs` 里有 0~100 逐点比对
  的回归测试，改任一边都会被测试拦住。
- **`el()` 支持 SVG**：`public/js/ui.js` 的 `el()` 会对 SVG 标签走 `createElementNS`。
  用 `document.createElement('svg')` 得到的是 HTMLUnknownElement，里面的 path/text 会全部
  失效，图标退化成一行文字 —— 文档页的开头图标就踩过这个坑。
- **主题只靠变量切换**：`[data-theme="dark"]` 只覆盖 `:root` 里的变量，组件不做任何分支判断。
  新增组件时**不要写死颜色**，用变量；二维码区域必须保持白底（`--qr-bg` 在深色下仍是白色），
  否则手机扫不出来。
- **文档页的滚动监听挂在 `#main` 上**，不是 `.doc-scroll` —— 后者没有自己的滚动条，
  挂错地方会让左侧目录高亮一直停在某一项上。
- 地址栏支持 `?theme=dark` / `?theme=light` 直接指定主题（会写入 localStorage），调试两种配色时很方便。
- `test/seed-demo.mjs` 可以在任意目录造一份演示数据，配合 `QQBOT_DATA_DIR` 起一个隔离实例，
  用来核对界面而不动你的真实数据：
  ```bash
  node test/seed-demo.mjs /tmp/demo
  QQBOT_DATA_DIR=/tmp/demo PORT=3322 node server/index.js
  ```
- 改了 `public/` 下的源码后，记得 `npm run build` 重新生成单文件版，否则页面还是旧的。
  `npm start` 时服务也会自动检查并重建。
- 改数据模型时注意：`Doc` 用的是**深合并**（`server/store.js` 的 `deepMerge`）。给已有的嵌套
  对象新增默认字段（例如往 `config.reply` 里加一项）在老实例上也能生效；浅合并会让老用户的
  整段 `reply` 覆盖掉默认值，新字段永远拿不到。`test/engine.mjs` 里有对应的回归测试。
